## 关键决策

- **路由位置**：recipe 前缀走 `SubagentManager.invoke` 内部判断，不在 AgentManager 顶层另开入口。理由：subagent dispatch 已是「统一调度所有非主会话执行」的汇聚点，加前缀判断保留单调度器原则（与 CLAUDE.md Boundaries「不归一多 CLI 协议」原则呼应——recipe 是产品抽象不是 CLI 协议）。
- **步骤类型**：仅 `agent`（必须 `agent_type`）+ `shell`（必须 `command: string[]` + 可选 `cwd`/`timeoutMs`/`allowed_files`）。不做 `parallel` / `conditional` / `loop`（避免迷你 DSL 陷阱；后续按需扩展）。
- **shell cwd 边界**：复用 ScopeGuard 同款 `safeRealpath` 检查；不允许 `..` 跳出 workingDirectory；无 workingDirectory 时 shell 步直接拒绝（agent 步无 workingDirectory 也能跑）。
- **取消语义**：cancel 触发 `AbortController.abort()`；`runAgentStep` 用 `Promise.race` 立即抛 `BizGraphError('Cancelled', RECIPE_RUN_FAILED)`；持久化 `status='cancelled'`。
- **RecipeRunRequest 输入类型**：从 `SubagentInvokeArgs` 抽离（`src/shared/types/recipe.ts` 不依赖 agent 类型以避免循环）；`parentSessionId`/`nodeId` 可选。
- **adapter 不引入 recipe 概念**：`DISPATCH_SUBAGENT_TOOL_SCHEMA` 的 `agent_type` 从 enum 改成 regex `^recipe:[a-z][a-z0-9-]*$|^[a-z][a-z0-9-]*$`，保持 schema 通用。
- **数据可移植**：recipe 元数据 + 完整 yaml_text 都入库（`recipes.yaml_text` 列），方便后续「导出 recipe」功能；运行历史分离到 `recipe_runs`（不冗余存 yaml_text）。

## 审查结论记录

- T6 实现时遇到 abort signal 未传播给 SubagentManager.invoke 的 mock，导致 cancel 测试超时。修复：`runAgentStep` 用 `Promise.race` + `signal.addEventListener('abort')` 主动 reject，确保持久化的 cancelled 状态可观察。
- T5 实现时误用不存在的 `getUserDataPath` 函数，改为 `app.getPath('userData')` 直接调 Electron（`recipe-manager.ts` 不复用 `env.ts` 的封装以减少耦合）。
- T8 实现时 IPC 错误包装丢失了 `code` 字段。修复：handler 内直接 `throw new BizGraphError(message, ErrorCode.X)`，透传 `toJSON()`；运行时 typecheck 错误（缺 recipeId/错类型）抛 `IpcError`。
