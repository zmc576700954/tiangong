## 目标

为 BizGraph 多用户实时画布（Phase D10 系列）建立**冲突解决策略层**：
- 文本字段走 Yjs CRDT 自动合并
- 状态机字段（status / severity）非法转换自动拒绝 + rollback
- 身份字段（id / graphId / createdAt）不可写
- 结构化字段（position / strength）按 Lamport 时间戳决胜
- 冲突报告通过 toast + LintPanel 给用户可见反馈

## 设计要点

**自洽设计**：D10a/b/c 三个 worktree 当前未合并（都停在 `341435a`），所以 D10d
不依赖它们的成果，自己实现 `getOrCreateRealtimeDoc(graphId)` 的最小内存注册；
当 D10a/c 接入时把工厂替换为真实现，resolver 不变即可工作。

**观测-回滚模式**：
- 监听顶层 `nodes/edges/bugs` map 的 `add/delete/update`
- 每个 entity 内部字段 observer 单独挂载（处理 entity 整体替换）
- 拒绝时用 `Y.transact(doc, () => map.set(field, prev), 'conflict-rollback')`
  包装回滚，并用 `event.transaction.origin === 'conflict-rollback'` 短路
  防止 observer 无限递归

**Lamport 持久化**：每字段 Lamport 时间戳存在 `doc.getMap('meta')`，
key 为 `lamport:<entity>:<id>:<field>`，value 是编码后的 `{clock, actorId}`。
首次写入放行 + 写 meta；并发时远端 clock 更新则回滚本地并产生
`lamport-loser` 报告（用于观察，不阻塞写入）。

**字段策略表**（`NODE_FIELD_RULES` / `EDGE_FIELD_RULES` / `BUG_FIELD_RULES`）：
- identity-immutable: id / graphId / createdAt / source / target / nodeId
- state-machine: status (节点走 `validateNodeTypeTransition`),
  bug.status (走 `validateBugTransition`), bug.severity
- text-crdt: title / description / wikiContent / communitySummary / label / dataFlow
- lamport-ordered: position / parentId / ownerRole / strength
- last-write-wins: type / updatedAt / metadata / content / edgeType / communityId
