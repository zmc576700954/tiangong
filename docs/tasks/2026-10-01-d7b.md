## 关键决策

- **状态机扩展**：`accepted → rolled_back` 是单向（用户撤回），不设计 `rolled_back → accepted`（再撤回语义混乱）。`discarded → pending` 给"误丢弃→恢复"留出口。两条新转换均不影响现有 accept / discard 行为。
- **rollback 段落定位**：用 `^## <title>\s*$` 行匹配锚定 + 找下一个 ## 标题行作为段末索引；段首回退 1 个 `\n`（accept 时拼接遗留）、无下一标题时连段尾 `\n` 一并吃掉。简单稳健，对用户手工追加的下一节保留段间分隔符。
- **new-page rollback**：直接删节点 + wiki-link/semantic 边，FK CASCADE 兜底；节点已被用户删 → skipped 记录到 RollbackResult。
- **审计粒度**：仅记录到 `rollback_actions` JSON 数组；不引入新表。审计读取通过 `listHistory` 即可。
- **30 天窗口**：仅 rolled_back 受 sinceIso 过滤；accepted 不限（用户采纳历史是永久资产）。`sinceIso` 默认 = `now - 30d`。
- **UI Tab 切分**：Pending Tab 复用原 batch selection + accept/discard；History Tab 只读 + 撤回入口（accepted）/ 灰显 + hover 步骤（rolled_back）。不设计"再采纳"以避免回退到 Pending 队列。
- **RollbackResult 部分回滚**：append-log 段落被用户手工改 → skipped；new-page 页面被用户删 → skipped。两种情况都把 skipped 计数显示给用户，不静默失败。
- **IPC 错误**：rollback 抛 `IPC_INVALID_ARGUMENT`（status 非 accepted / itemId 不存在 / 缺 deps），前端 toast + banner 提示。
