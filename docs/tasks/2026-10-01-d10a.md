## 目标

为 BizGraph 引入 Yjs CRDT 文档模型：

- 每 graph 一个 `Y.Doc`，doc name = `graph:<id>`，三个顶层 `Y.Map`：`nodes` / `edges` / `meta`
- SQLite 仍是 source of truth，Y.Doc 是 mirror（lazy 创建 + hydrate）
- WS server（端口默认 1234，可关闭）使用 `y-protocols/sync` 二进制协议把远端 update 路由到本地 doc → 反向触发 SQLite 落库（带状态机校验）
- 任何现有 IPC 写入路径不变；mirror 通过 repository 写入后回调接入

## 关键决策

### 1. SQLite 仍是 source of truth，Y.Doc 是 mirror

- repository 写入路径完全不变；mirror 通过 `YjsManager.onAfterNodeUpsert/...` 回调在 SQLite 写入之后注入。
- 反向：WS server 收到远端 `messageYjsUpdate` → `registry.applyRemoteUpdate(graphId, update, { source: 'remote' })` → 翻译成 deltas → 远端订阅者（`YjsManager.handleRemoteNodeChange`）写 SQLite。
- 优势：现有 IPC 接口、状态机校验、WikiLinkService 边界都不动；Y.Doc 仅作为内存中的同步层存在。

### 2. `applyRemoteUpdate` 使用 `nodesMap.observe` 而不是 `afterTransaction`

- 第一版用了 `doc.once('afterTransaction', tx => tx.changed.get(nodesMap))`，但 Yjs 的 `tx.changed.get(YMap)` 返回的 Set 里是 **key 名（字符串）**，不是 inner Y.Map 实例，迭代时拿不到对象。
- 改用 `nodesMap.observe(ev => ev.keys)`：`ev.keys` 是 `Map<string, { action: 'add' | 'update' | 'delete'; oldValue }>`，提供每键的精确动作语义。
- `add` → create；`update` → update；`delete` → delete；inner 为空（清空）也按 delete 处理。

### 3. `insertRemoteNode` 用原始 INSERT，保留 payload 的 id

- `NodeRepository.create()` 用 `generateId('node')` 生成新 id；CRDT 语义要求远端写入的 id 必须被尊重，否则两个 client 各自 create 同一个 id 的节点会产生不同 SQLite 行。
- 在 `YjsManager` 里新增 `insertRemoteNode(payload)` 方法，直接 `INSERT INTO nodes ...`，不绕开状态机校验（payload 的 status 已经在 `handleRemoteNodeChange` 入口经过 `validateNodeTypeTransition`）。
- 这违反了"不绕开 repository"原则，但有充分理由并在方法注释里明确标注。

### 4. WS server 默认 disabled

- `settings.realtime.enabled` 默认 `false`：主进程内仍维护 Y.Doc（mirror），但 WS server 不监听端口。
- 避免 worktree 并行时端口 1234 冲突；用户在 settings.json 显式开启才暴露。

### 5. ambient .d.ts 补齐

- `lib0`（yjs / y-protocols 的底层依赖）不发布 .d.ts。补齐最小集合：`lib0/encoding` / `lib0/decoding`（仅用到 `createEncoder` / `createDecoder` / `writeVarUint*` / `readVarUint*`）。
- `yjs` 的 `Doc`（ObservableV2 子类）继承 lib0 基类，补齐 `on / once / off / emit / destroy`。
- `YMap.observe / unobserve` 已经由 yjs 自带 `AbstractType.observe` 暴露（泛型 EventType = YMapEvent），不需要额外增强。

### 6. `hydrateFromSqlite` 不用 `GraphRepository.get()`

- 原代码用 `GraphRepository.get(graphId)` 读 graph 元数据，但 `get()` 内部会查 `bug_nodes` 表（即使结果未使用）。
- 测试用 in-memory SQLite 没有 `bug_nodes` 表，会报 `SQLITE_ERROR`。
- 改成直接 `SELECT * FROM graphs WHERE id = ?`，避免触发无关查询。
