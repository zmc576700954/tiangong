## 目标

接入 A2A（Google 2025 提出的跨进程 Agent 通信协议），让 BizGraph 不再是单进程孤岛：

- **Server 角色**：BizGraph 暴露自身能力（graph query / agent dispatch / wiki search），外部 Agent 通过 HTTP + SSE 调用
- **Client 角色**：BizGraph 注册远程 A2A agents，作为 `a2a:<name>` 子代理类型接入 `SubagentManager` 主调度

## 任务清单（6 子任务）

### D9-1：A2A 类型定义

- 新增 `src/shared/types/a2a.ts`
- A2A spec 关键消息映射：
  - `A2ASendMessageRequest` / `A2AStreamMessageRequest`
  - `A2ATask` / `A2AMessage` / `A2APart`（TextPart / FilePart / DataPart）
  - `A2AArtifact` / `A2AStatus`（working / completed / failed / canceled / input-required）
  - `A2AAgentCard`（name / description / url / version / capabilities / skills）
- 与 `AgentSessionConfig`（`src/shared/types/agent.ts`）双向映射：`config.agentName → card.name`、`config.allowedFiles → artifact.metadata.allowed_files`、`config.modelId → card.skills[].modelId`
- 测试：双向映射 roundtrip × 6 case

### D9-2：A2A Server 端

- 新增 `src/main/a2a/server.ts`
- HTTP + SSE endpoint — **采用 Node 原生 `http` / `https`**，不引入 Express（理由：基座坚持零非必要依赖；A2A 协议本身只需 3 个 endpoint，原生 http 足够）
- 路由：
  - `GET /.well-known/agent-card.json` → 返回本机 `AgentCard`（与 Settings 配置同步）
  - `POST /v1/message:send` → `SendMessage`，映射到 `AgentManager.startSession()` + `sendCommand()`，同步返回 `Task`
  - `POST /v1/message:stream` → `StreamMessage`，SSE 流式回传（`text/event-stream`，`event: artifact|status|message`）
  - `GET /v1/tasks/:id` → `GetTask` 查询历史
  - `GET /v1/tasks` → `ListTasks` 列表（带 `?contextId=&status=` query）
- 监听端口：默认 `A2A_SERVER_PORT=8089`（环境变量）+ Settings 覆盖
- 服务端默认 **关闭**，需 Settings `a2aServer.enabled=true` 才启动
- 任务持久化：复用 `chat_threads` + `chat_messages`（不新增表）— `chat_threads.session_id` 即 A2A `taskId`，`metadata.task_kind='a2a'` 标识
- 测试：endpoint 路由、message:send roundtrip、stream:stream SSE 事件序列、agent-card 同步、404 / 405 处理 × ≥8 case

### D9-3：A2A Client 端

- 新增 `src/main/a2a/client.ts`
- `A2ARemoteAgent` 结构（`src/shared/types/a2a.ts`）：
  ```ts
  interface A2ARemoteAgent {
    name: string                       // 'a2a:<name>' 子代理类型中的 <name>
    endpoint: string                   // https://host:port
    apiKey?: string                    // 可选 bearer token（加密存储）
    tlsVerify?: boolean                // 默认 true
    timeoutMs?: number                 // 默认 30000
    capabilities?: A2AAgentCapability[] // 缓存远端 AgentCard.skills
  }
  ```
- Settings 新增 `a2a.remoteAgents: A2ARemoteAgent[]`（加密字段沿用 `safeStorage` / AES fallback）
- 在 `SubagentManager` 注册为 `a2a:<name>` 类型：
  - 启动时 `SubagentManager.registerType()` 批量注册
  - `scopeStrategy: 'fresh'`（远程 agent 不共享本地文件）
  - `isWriteCapable` 跟随远端 `AgentCard.capabilities` 标记
- 调用流程：`SubagentManager.invoke({ agentType: 'a2a:<name>' })` → Client 包装为 `StreamMessage` 请求 → 通过 SSE 接收 `artifact` 事件 → 拼装为 `SubagentResult` 返回
- 测试：远端 mock server 测试、bearer token 注入、超时处理、capabilities 缓存、错误传播 × ≥6 case

### D9-4：认证与安全

- **Server 端**：
  - 默认关闭 + API Key 鉴权（`Authorization: Bearer <key>`）
  - 可选 mTLS：`A2A_TLS_CERT_PATH` + `A2A_TLS_KEY_PATH` 环境变量加载
  - 启动时校验：API key 至少 16 位（防误配）、端口未占用
  - 路径安全：远程 agent 调用产生的文件改动受 `ScopeGuard` 兜底（沿用 `AgentManager.startSession` 已集成 ScopeGuard 的路径，**不另开边界**）
- **Client 端**：
  - API Key 加密存储（沿用 `encryptSettings` / `decryptSettings`，不重写）
  - HTTPS 证书校验默认开启（`tlsVerify: false` 仅开发环境 + 警告日志）
  - 远端 endpoint 白名单：`https://` 或 `http://localhost` 才允许（拒绝 `file://` 等）
- **路径边界**：远端 agent 不声明 `allowedFiles`，本地写文件必须经 `ScopeGuard` 显式声明（与本地 `dispatch_subagent` 语义一致）
- 测试：bearer 401 / 403 拒绝、空 key 启动失败、远端路径白名单拒绝、mTLS 加载（mock） × 嵌入 server.test / client.test

## 关键决策

### 1. HTTP 库选择：Node 原生 `http` 而非 Express

理由：基座坚持零非必要依赖（CLAUDE.md Boundaries 第 5 条「不归一多 CLI 协议」精神 — 不引入超出自身职责的中间件）。A2A 只需要 5 个 endpoint，原生 `http` 完全够用，路由用 `if-else` 或简单 switch 即可。Body 解析自写 200 行（按 A2A JSON Schema 反序列化）。

### 2. 任务持久化复用 `chat_threads`

不新增 `a2a_tasks` 表。`chat_threads.session_id` 已唯一，附 `metadata.task_kind='a2a'` 区分。`agent_logs` 已记录 session 结束事件。理由：基座原则「不承担删除语义不属于自己的数据」，A2A 任务生命周期与 BizGraph session 等价，没必要分表。

### 3. 客户端接入点：`SubagentManager.registerType`

不另开 `A2AManager` 类。与 Recipe 同模式（`subagent-manager.ts:149` 已用 `recipe:` 前缀路由）：注册自定义类型 + 在 `invoke()` 头部判断前缀转交 Client。理由：SubagentManager 已是「统一调度所有非主会话执行」的汇聚点，加 `a2a:` 前缀判断保持单调度器原则。

### 4. 服务端默认关闭

Settings `a2aServer.enabled` 默认 `false`。即使在 dev 模式也不自动启动 — BizGraph 是桌面应用，开放 HTTP 端口是攻击面，必须显式开启 + API Key。Settings 写入即热重启（监听端口变化）。

### 5. 不污染远端 LLM KV-cache

A2A Server 透传 prompt 时**不注入**BizGraph 内部 memory / scope 摘要。理由：CLAUDE.md Boundaries 第 3 条「不污染可复用 KV-cache prefix」，远端 LLM 视角下 BizGraph 是透明转发方，不应在 prompt 中夹带本地状态。

### 6. UI 在 SettingsPanel 内，不独立 FloatingPanel

理由：A2A 配置是低频变更操作（启用一次、偶尔测试连接），不需要常驻画布浮层。SettingsPanel tab 模式已支持。**不**触发 CLAUDE.md「FloatingPanel 共享外壳」抽取条件（当前仍为 2 个浮层：Settings / Recipes — 不含 A2A）。

### 7. mTLS 作为可选，不强求

mTLS 配置复杂（证书生成、客户端 CA 分发），基座版仅支持 bearer token + mTLS 环境变量配置。客户端 mTLS 暂不支持（需双向，证书管理复杂度高）。若用户需要，后续可在 Settings 加 TLS 客户端证书导入。

### 8. 不实现 A2A Push Notification

A2A spec 包含 `tasks/pushNotificationConfig`（webhook 推送），D9 不实现。SSE 流式 + 短轮询已覆盖 95% 用例。后续可作为 D9.1 增量。
