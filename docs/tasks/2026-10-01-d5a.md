## 目标

引入 Block Goose `sub_recipes` 概念的序列版本：Recipe 可以按数组顺序引用其他 Recipe（`recipe: <other-id>`），outputs 跨步骤累积供后续 `${outputs.<name>.field}` 模板引用。

## 关键决策

- **拓扑排序基座版 = 数组顺序**：sub_recipes 的执行顺序由数组下标决定（D5b 引入 parallel / on_failure 后再解析 depends_on）
- **跨 Recipe 循环 = 校验失败**：把 Recipe graph 视作有向图，3 色 DFS 遇到 GRAY 邻居即环；校验失败的 Recipe 从缓存丢弃而不抛错（避免单坏 YAML 拖崩所有 Recipe）
- **Recipe 引用存在性 = 校验失败**：同样在 `validateGraphs` 里抛出，单坏 YAML 不影响其它
- **sub_recipe.inputs 模板渲染**：用 `applyTemplate` 同时支持 `${input.x}` 和 `${outputs.<prev>.field}`；`outputs.<prev>.field` 缺字段抛错（避免静默错误）
- **out_throws when not found**：与 `${input.x}` 的"required=true 抛错"一致
- **subRuns 不持久化**：D5a 仅内存返回（D5c / 可视化可能需要 DB 字段 → 等需求确定后再迁移 schema_version）
- **基座 v1 完全兼容**：`run()` 自动判断 `sub_recipes` 决定走 `runDAG` 还是 `runSingle`；无 sub_recipes 的 Recipe 走原路径，零行为变化
